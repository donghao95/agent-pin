# 默认 Pin 策略

当 `~/.agent-pin/pin-preferences.md` 已存在但没有覆盖当前场景时，使用本策略。偏好文件不存在时，先执行 `preference-initialization.md` 创建偏好文件。

## 默认姿态

偏保守。桌面 Pin 会占用用户视觉空间，所以只有内容在聊天之外仍有持续价值时才 pin。

## 应该 Pin 的场景

- 用户明确要求 pin、贴到桌面、显示到桌面或创建 Agent Pin。
- 长任务完成，最终结果需要留在桌面上。
- 发现高风险问题、阻塞问题或重要失败。
- 生成了图片或视觉结果，用户可能需要检查。
- 关键决策、最终建议或下一步摘要不应该淹没在聊天里。

## 不应该 Pin 的场景

- 普通聊天或快速问答。
- 内部推理、原始日志或完整聊天记录。
- 未验证的猜测。
- secrets、tokens、credentials、个人隐私或敏感业务数据，除非用户明确要求且内容已脱敏。
- 同一信息刚刚已经 pin 过。
- Agent Pin 自身不可用；这种情况只在聊天里报告。

## 失败处理

只有当失败本身是任务结果，或是用户稍后需要处理的持久阻塞时，才 pin 失败。

适合 pin 的失败：

- CI/build/test 经过长时间运行后失败，且下一步明确。
- 代码审查发现高风险 bug。
- 部署或构建失败，用户可能会切换上下文，需要稍后继续处理。

只在聊天里说的失败：

- Agent Pin 未运行。
- CLI 输入或参数格式错误。
- 临时网络错误、权限未授权等需要继续对话处理的问题。
- 错误信息包含 secrets 或敏感数据。

短失败用 `status --level error`。需要背景和下一步时，用 `markdown` 或 `push`。

## 命令选择

- `status`：一句短状态、成功、警告或失败。
- `markdown`：可读结论、审查结果、决策或下一步摘要。
- `image`：一张本地图片，可带说明。
- `push`：混合 blocks，尤其是 Markdown + image 或 status + Markdown。
- `list`、`show`、`hide`、`hide-all`：只在用户要求或继续既有 Pin workflow 时使用。

Agent 调用 CLI 时默认加 `--json`。

## 内容形态

- 标题：短名词短语，通常不超过 24 个中文字符。
- Status text：一句话。
- Markdown：先给结论，再给最少证据或下一步。
- 避免过宽 Markdown 表格；必须使用表格时列数要少、标题要短。
- 不要 pin 原始命令输出，先总结。
