# Agent Pin 偏好初始化

本文件用于第一次使用 Agent Pin skill 时，帮助 Agent 通过多步对话建立用户的 pinning 偏好。

目标不是让用户填长表，而是建立一个够用的本地偏好文件：

```text
~/.agent-pin/pin-preferences.md
```

## 原则

- 一次只问一个问题。
- 问题应具体、易回答。
- 用户可以跳过任何问题。
- 不要把用户的一次性选择写成永久规则。
- 只有用户明确表达“以后”“默认”“总是”“不要再”这类持久偏好时，才写入长期规则。
- 偏好文件只存本机，不提交到仓库。

偏好文件不存在时必须创建。偏好文件存在时，只有用户明确要求更新，或给出“以后不要 pin 测试失败”“以后长任务完成都 pin 一下”这类持久纠正时，才更新该文件。

如果偏好文件已经存在但无法读取、格式明显损坏或内容互相冲突，先告诉用户问题，并询问是否重建。用户同意后，把旧文件保留为带时间戳的备份，再按本流程重建。

## 提问方式

分步询问，不要一次把所有问题丢给用户。每得到一个回答，就根据回答调整下一步问题。

建议开场：

```text
我还没有你的 Agent Pin 偏好。为了避免以后乱贴桌面，我先问几个很短的问题；你可以随时说“跳过”。
```

## 问题 1：自动 pin 的范围

先问：

```text
你希望我在什么情况下主动创建桌面 Pin？

例如：
1. 只有你明确说“pin/贴到桌面”时。
2. 长任务完成、发现高风险问题、生成图片结果时可以主动 pin。
3. 尽量主动，把重要结论都 pin 出来。
```

记录规则示例：

```md
## 自动 pin 范围

- 默认只在用户明确要求时 pin。
```

或：

```md
## 自动 pin 范围

- 长任务完成、生成图片、发现高风险阻塞问题时，可以主动 pin。
- 普通聊天和短问答不主动 pin。
```

## 问题 2：失败是否 pin

根据问题 1 再问：

```text
任务失败时你希望我 pin 吗？比如 CI 失败、构建失败、审查发现严重问题。
```

可选记录：

```md
## 失败处理

- CI/build/test 长任务失败可以 pin。
- 临时工具错误、Agent Pin 未启动、权限问题只在聊天里报告，不 pin。
```

## 问题 3：内容类型偏好

问：

```text
你更希望桌面 Pin 放什么内容？

例如：
- 只放结论和下一步。
- 结论 + 少量证据。
- 图片结果也直接 pin。
- 不要 pin 长日志或完整聊天记录。
```

记录：

```md
## 内容偏好

- Pin 内容应短，先给结论，再给下一步。
- 不 pin 原始日志或完整聊天记录。
- 图片结果可以 pin。
```

## 问题 4：敏感信息边界

问：

```text
有哪类内容绝对不要 pin 到桌面？比如客户信息、路径、截图、错误日志、密钥相关内容。
```

默认写入：

```md
## 敏感信息

- 不 pin secrets、tokens、credentials。
- 不 pin 个人隐私和敏感业务数据，除非用户明确要求且内容已脱敏。
```

## 问题 5：展示偏好

问：

```text
Pin 默认展示上有什么偏好吗？比如是否置顶、常用宽度、是否更喜欢 status/markdown/image。
```

没有偏好时使用：

- Agent CLI 调用默认加 `--json`。
- Agent 自动创建 Pin 时默认用 `push`。
- 默认置顶。
- 默认宽度和 `height: auto`。
- 图片通过 CLI 创建后不依赖源文件原路径。

## 偏好文件模板

写入 `~/.agent-pin/pin-preferences.md` 时使用以下结构：

```md
# Agent Pin Preferences

Updated: <ISO 8601 timestamp>

## 自动 pin 范围

- ...

## 失败处理

- ...

## 内容偏好

- ...

## 敏感信息

- 不 pin secrets、tokens、credentials。
- 不 pin 个人隐私和敏感业务数据，除非用户明确要求且内容已脱敏。

## 命令默认值

- 使用 `agent-pin --json`。
- Agent 自动创建 Pin 时优先用 `push --file`。
- `markdown`、`image`、`status` 只在用户明确要求或手写调试时使用。
- 图片创建成功后不依赖源文件原路径。
- 窗口: 默认置顶、默认宽度、`height: auto`。

## 学习记录

- <日期>: <用户明确纠正或新增偏好>
```

## 更新已有偏好

当用户说：

- “以后不要 pin 测试失败”
- “以后所有长任务完成都 pin”
- “以后图片结果都贴桌面”
- “不要再把这种错误 pin 出来”

应更新 `学习记录` 和对应规则。

不要因为用户一次性说“这次不用 pin”就写入长期规则，除非用户说“以后”。
