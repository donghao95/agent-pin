# Pin 偏好初始化流程

在以下场景使用本流程：

- `~/.agent-pin/pin-preferences.md` 不存在。创建 Pin 或判断是否应该 pin 之前，先完成本流程并写入偏好文件。
- 用户明确要求初始化、个性化、调整、学习或更新 Agent Pin 行为。
- 用户给出持久纠正，例如“以后不要 pin 测试失败”“以后长任务完成都 pin 一下”。

如果只是一次性选择，例如“这次不用 pin”，不要把它写成长期偏好。只有用户表达的是持续习惯、规则或纠正时，才更新偏好文件。

## 输出文件

最终偏好文件写入：

```text
~/.agent-pin/pin-preferences.md
```

如目录不存在，创建 `~/.agent-pin/`。

偏好文件不存在时必须创建。偏好文件存在时，只有用户明确要求更新，或给出“以后不要 pin 测试失败”“以后长任务完成都 pin 一下”这类持久纠正时，才更新该文件。

## 提问方式

分步询问，不要一次把所有问题丢给用户。每得到一个回答，就根据回答调整下一步问题。

## 第 1 步：默认主动程度

问：

```text
你希望 Agent Pin 默认更保守、平衡，还是更主动？
```

选项：

- 保守：只 pin 明确请求、最终交付物和高风险阻塞。
- 平衡：pin 明确请求、长任务结果、高风险问题、重要失败、视觉结果和关键决策。
- 主动：长任务或多步骤工作中，也更频繁 pin 进度/状态。

推荐默认：平衡。

## 第 2 步：必须 Pin 的场景

询问哪些场景应该总是 pin：

- 用户明确说 pin / 贴到桌面 / 稍后看 / 提醒我。
- 长任务完成。
- 代码审查结论。
- CI/build/test 失败。
- 高风险 bug 或安全问题。
- 生成图片或视觉结果。
- 架构或产品决策。
- 下一步行动清单。

允许用户补充自定义场景。

## 第 3 步：失败处理

先解释区别：

```text
失败 pin 的价值是让“需要稍后处理的阻塞结果”留在桌面；代价是临时错误也可能打扰你。
```

再问：

```text
失败时你希望怎么处理？
```

选项：

- 只 pin 重要失败：任务级失败或持久阻塞才 pin；临时 CLI/network/input 错误只在聊天里说。
- 默认不 pin：失败只有你明确要求时才 pin。
- 任务失败都 pin：build/test/CI/review/deploy 失败都 pin，但工具自身故障仍只在聊天里说。

推荐默认：只 pin 重要失败。

几乎固定的规则：

- 不 pin “Agent Pin 未运行”；只在聊天里报告。
- 不 pin CLI 参数或输入格式错误。
- 不 pin 包含 secrets 或敏感数据的错误。

## 第 4 步：内容密度

问：

```text
你希望 pin 的内容多短？
```

选项：

- 极短：status 风格，一句话，通常 80 个中文字符以内。
- 简洁：短摘要 + 下一步，通常 400 个中文字符以内。
- 详细：可独立阅读，通常 1000 个中文字符以内。

推荐默认：简洁。

## 第 5 步：隐私边界

问：

```text
哪些内容永远不要显示到桌面 Pin 上？
```

可提示例子：

- secrets、tokens、credentials。
- 个人隐私信息。
- 客户或公司敏感数据。
- 完整聊天记录。
- 原始日志。

保留用户补充的原话。

## 第 6 步：展示偏好

只有当用户看起来关心展示方式时才问：

```text
Pin 默认展示上有什么偏好吗？比如是否置顶、常用宽度、是否偏好 status 而不是 markdown。
```

没有偏好时使用：

- Agent CLI 调用默认加 `--json`。
- 默认置顶。
- 默认宽度和 `height: auto`。
- 一句状态用 `status`；摘要用 `markdown`；混合内容用 `push`。
- 图片通过 CLI 创建时复制到 `~/.agent-pin/images/`，不依赖源文件原路径。

## 偏好文件模板

按下面格式写入：

```markdown
# Agent Pin 偏好

Version: 1
Updated: <ISO 8601 timestamp>

## 默认姿态

- 模式: Balanced | Conservative | Proactive
- 摘要: <一句话说明>

## 总是 Pin

- <场景>

## 通常不 Pin

- <场景>

## 失败处理

- 模式: Important failures only | Never by default | Always for task failures
- Pin 条件: <规则>
- 只在聊天里说: <规则>

## 内容风格

- 密度: Tiny | Concise | Detailed
- 标题风格: 短名词短语
- Markdown 风格: 先结论，再给最少证据或下一步

## 隐私边界

- 永不 Pin: <项目>

## 命令默认值

- 使用 `agent-pin --json`。
- 短状态优先用 `status`。
- 简洁摘要优先用 `markdown`。
- 单张本地图片优先用 `image`。
- 混合 blocks 优先用 `push`。
- CLI 会把图片复制到 `~/.agent-pin/images/`。
- 窗口: 默认置顶、默认宽度、`height: auto`。

## 学习记录

- <用户给出的持久纠正，带日期>
```

保持简洁。这是给 Agent 执行用的偏好文件，不是日记。
